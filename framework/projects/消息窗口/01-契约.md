# 契约 · 消息窗口

> 只有总控能改；模块要改先报总控，不许自己动手。

## 全局约定

- 运行环境：node（ESM，.mjs），用 node 内置 fetch/http；外部依赖 ffmpeg（系统安装）
- 代码位置：modules/<模块名>/，出了自己目录不许写
- **零数据库**：本项目不建库、不存业务数据；只有配置文件和临时文件
  - 配置：config.json（各 bot token→归属项目、项目接收地址、转换器地址+key）——含密钥，不进 git；模板 config.example.json
  - 临时文件：临时文件/ 目录，用完即删
- 配置填法：转换器一律「地址 + key」两栏；填 localhost=本地，填云端=线上，同一填法，代码不分家
- 项目之间：默认隔离；本窗口要用模型 → 走「模型网关」契约写明的接口
- **格式化输出（2026-10-05 定稿）**：**两边同格式**——项目回传的 markdown 原样转发；微信接口自带渲染（表格/加粗/链接/标题实测都出效果，用户截图实锤），零处理；TG 走 sendRich（markdown→HTML：转义 + 标签感知切分 + 失败降级纯文本，移植自现役 bot）。⛔ 不做「微信剥格式」——微信只认纯文本是没验证的错结论，见教训档第 28 条
- 任务状态：待认领 → 进行中 → 待验收 → 完成 / 打回

## 模块清单

| 模块 | 对外接口 | 依赖 |
|---|---|---|
| access | 收：轮询各通道新消息；发：send(通道, chatId, 内容) | convert |
| convert | normalize(原始消息)→标准消息；toText(语音文件)→文本 | 无（ffmpeg 为系统依赖） |
| route | resolve(token)→项目名；dispatch(标准消息)→推给归属项目 | access |
| api | HTTP：POST /send；GET /health | access |

## 标准消息（全窗口统一形状）

    { 类型: 文字|语音|图片|视频, 文件: 临时文件路径|无, 文字: 内容或说明, 通道: tg|微信, chatId, 项目 }

## 接口明细

### access

- **TG**：按 config.json 的 token 列表轮询 getUpdates；发 = **sendRich 富文本**（markdown→HTML，文字类一律走它），唯一判据 `message_id`；单条拉取/归一失败：打日志跳过、照常推进 offset（坏消息不卡通道、不缓存重试）
- **微信（iLink 协议，移植自现役 bot）**：长轮询 getupdates 收（游标记内存）；发 = sendmessage，**三件套防丢**：① 唯一判据 = 返回带 `message_id`（ret:0 无 id = 服务端静默丢）② 自动重试 2 次（救瞬态）③ 最终失败显式报告绝不静默；必须带 client_id + from_user_id:''，回信用入站带来的 context_token（按发送者缓存，记内存）
- **微信语音**：服务端已自带转写（voice_item.text），直接当文字用，不过本地转写链
- **微信图片**：收 = image_item → media.full_url 下载 + AES-128-ECB 解密（`aeskey` hex / `aes_key` base64 两型归一，移植自现役 bot）+ 魔数嗅探 → 临时文件归一 jpg/png。**发（2026-10-05 接线，真机验收过）**：getuploadurl 拿预签名 → AES-128-ECB 加密传 CDN → sendmessage(image_item)；实测本机服务端直接回**完整预签名 URL `upload_full_url`**（CDN 域名 novac2c.cdn.wechat.com），openilink SDK 样本的 upload_param 拼接法留作后备形状、两种都认；aes_key 参数 = base64(hex字符串)；成功判据与文字同（message_id 三件套）；请求形状来源：openilink SDK（github.com/openilink/openilink-sdk-python / -sdk-go）+ 本机探针实测

### convert

- normalize：文字直接过；图片/语音/视频下载落 临时文件/；**语音一律 ffmpeg 归一成 mp3（16k 单声道）**，视频保持原样传递
- toText：配置开关开了才调转换器；**给 `模型名` 就走模型网关 /call 信封 {模型名, 输入}，不给就直连地址**——转完连原文一起返回
- **图片归一（2026-10-05 定稿默认）**：各通道来的图，**不是 jpg/png 的一律转成 jpg/png** 再进标准消息、再给模型网关——jpg/png 是视觉模型的通吃格式；具体清单以网关两头实测为准（暂未实测）

### route

- resolve(token) → 归属项目（config.json 映射，这就是零数据库的由来）
- dispatch：把标准消息 POST 到该项目在配置里登记的接收地址；投递失败即时报错、**不缓存**（零数据的代价，明知接受）
- **打包**：同一顾客 `打包间隔秒`（默认 5）内连发的消息攒成一批，静默到期才封包投递——多段语音 ffmpeg 拼成一条音频、转写整段只做一次；**图片一张一包**（标准消息.文件 = 本地临时路径，同机项目直接读）；**忙闸门（2026-10-05 定稿）**：上一包在等项目回复期间，新消息全攒住不投递，回复送达（/send 成功）立刻把攒的一起封包；投递未全成或 120 秒没回音强制放行，永不锁死顾客；文字连成一句、**段间自动补逗号**（前段已有句读则不重复加）；标准消息多两个字段：`段数`、连好的 `文字`
- **回显**：项目配置 `回显: true` 时，语音转写出的文本原样回给发送者（`我：…`）；**拉取/归一/转写任一环失败也回「语音转文字失败，请再说一次」**——让顾客看见自己说的话、自己纠正发音；默认关

### api

- POST /send {token, 通道, chatId, 类型, 文件|文字} → 交 access 发送（token=项目自己的 bot token，项目自己知道）；文件支持 **URL / file_id / 本地临时路径**（本地路径走 multipart 上传，sendPhoto 系字段名砍 `send` 前缀——slice(3) 出过 `dphoto` 潜伏 bug）；**通道:'微信' 走 runner 注入的微信发送器**（wx 实例和 context_token 只在 runner 内存，重启后顾客发条消息即补令牌；现已接发图，微信发文字未接——access.send 仍只认 tg）
- GET /health → {ok:true}
